R-01 NoFactura (CUFE) Incorrecto o Faltante NORMATIVA Descripción: El campo NoFactura debe contener el CUFE (Código Único de Facturación Electrónica), no el número de factura convencional.

Consecuencias:
  • La factura no viaja a la DIAN
  • Rechazo automático por MIPRES
  • Sanciones del Ministerio de Salud
  • Pérdidas económicas por no cobro
  • Incumplimiento normativo fiscal
⚠️ NOTA IMPORTANTE: Actualmente este campo se ingresa manualmente debido a que se requiere autorización del Ingeniero Senior para conectar la base de datos institucional y extraer automáticamente el CUFE.
ALTA
(Mientras no haya conexión a BD)		 CRÍTICO CRÍTICO Mitigación inmediata:
  • Consultar el CUFE en el sistema SALUS (sistema anterior con acceso a BD)
  • Verificar con el manual XLSX de Swagger proporcionado por la clínica
  • Validación de formato CUFE (96 caracteres alfanuméricos)
  • Consultar a los ingenieros para verificar CUFE en base de datos
  • Comparar datos impresos con registros de BD
  • Reportar inconsistencias al departamento de facturación
  • Capacitación al personal sobre CUFE vs. No. Factura
Solución definitiva:
  • Solicitar autorización formal al Ingeniero Senior para conexión a base de datos institucional
  • Implementar extracción automática de datos desde la BD
  • Autocompletar CUFE, CodEPS, CUM y ConTec automáticamente
R-02 Digitación Incorrecta de ValorUnitFacturado y ValorTotFacturado OPERATIVA Descripción: Errores al digitar el valor unitario que afectan directamente el valor total facturado (ValorTotFacturado = CantUnMinDis × ValorUnitFacturado).

Consecuencias:
  • Sobrefacturación o subfacturación
  • Glosas por parte de EPS
  • Pérdidas económicas para la clínica
  • Investigaciones del Ministerio de Salud
  • Sanciones económicas y administrativas
 MEDIA ALTO ALTO Mitigación inmediata:
  • Consultar valores en el sistema SALUS (sistema anterior con acceso a BD)
  • Verificar con el manual XLSX de Swagger proporcionado por la clínica
  • Cálculo automático de ValorTotFacturado en la interfaz
  • Realizar cálculos manuales para verificación: Cantidad × Precio
  • Consultar a ingenieros para verificar valores en base de datos
  • Comparar datos con registros impresos de BD
  • Reportar inconsistencias al departamento de facturación
  • Vista previa con resumen antes de enviar
  • Doble verificación para valores atípicos

  • Solicitar autorización formal al Ingeniero Senior para conexión a base de datos institucional
  • Implementar extracción automática de valores y tarifarios desde BD
  • Validación automática contra catálogos CUM y tarifarios SOAT/ISS
  • Alertas automáticas cuando valores difieren del catálogo
R-03 ValorEntregado Inconsistente con Prescripción OPERATIVA Descripción: El valor entregado no coincide con los precios y cantidades autorizadas en la prescripción. Ejemplo: 138 ítems entregados cuando la prescripción autoriza máximo 40, cada uno con precio individual de $4,737.

Consecuencias:
  • Rechazo automático por MIPRES
  • Devoluciones de facturación
  • Auditorías exhaustivas del Ministerio
  • Multas y sanciones económicas
  • Riesgo de demandas por sobrecostos
  • Pérdida de credibilidad institucional
 MEDIA CRÍTICO CRÍTICO Mitigación inmediata:
  • Consultar datos de prescripción en el sistema SALUS
  • Verificar cantidades autorizadas con el manual XLSX de Swagger
  • Validación manual contra datos de la prescripción original
  • Realizar cálculos manuales: CantidadEntregada × PrecioUnitario
  • Consultar a ingenieros para verificar límites en base de datos
  • Comparar con límites autorizados impresos
  • Alerta visual cuando la cantidad supere el máximo autorizado
  • Reportar discrepancias al departamento de facturación
  • Bloqueo de envío si hay inconsistencias críticas detectadas manualmente
Solución definitiva:
  • Solicitar autorización formal al Ingeniero Senior para conexión a base de datos institucional
  • Implementar validación automática contra datos de prescripción desde BD
  • Cálculo y verificación automática de límites autorizados
  • Trazabilidad completa de cálculos y validaciones realizadas
R-04 CantTotEntregada Diferente a Prescripción OPERATIVA Descripción: Error de digitación al registrar cantidades mayores o menores de las autorizadas en la prescripción o factura.

Consecuencias:
  • Inconsistencias en inventario
  • Rechazo de facturación
  • Devoluciones por EPS
  • Auditorías de control interno
  • Pérdidas económicas
 MEDIA MEDIO MEDIO Mitigación inmediata:
  • Consultar cantidades prescritas en el sistema SALUS
  • Verificar con el manual XLSX de Swagger de la clínica
  • Validación numérica estricta del campo en la interfaz
  • Comparación manual con cantidad prescrita original
  • Consultar a ingenieros para verificar datos en base de datos
  • Comparar datos impresos con registros de BD
  • Alerta visual si difiere de la prescripción
  • Campo de justificación obligatorio para diferencias
  • Reportar inconsistencias al departamento de facturación
Solución definitiva:
  • Solicitar autorización formal al Ingeniero Senior para conexión a base de datos institucional
  • Implementar comparación automática con cantidad prescrita desde BD
  • Sugerencia automática desde prescripción original
  • Registro de auditoría de modificaciones
R-05 EstadoEntrega Mal Clasificado OPERATIVA Descripción: Selección incorrecta del estado de entrega (1: Entregado, 2: Parcial, 3: No entregado) que no corresponde con la realidad operativa.

Consecuencias:
  • Inconsistencias en reportes del Ministerio
  • Dificultad para seguimiento de entregas pendientes
  • Confusión en auditorías internas
  • Retrasos en cobros por estados incorrectos
  • Indicadores operativos erróneos
 MEDIA MEDIO MEDIO Mitigación inmediata:
  • Consultar estado real de entregas en el sistema SALUS
  • Verificar con el manual XLSX de Swagger proporcionado
  • Lista desplegable con descripciones claras en la interfaz
  • Validación cruzada manual con CantTotEntregada
  • Consultar a ingenieros o facturación en caso de duda
  • Comparar con registros físicos de entregas
  • Confirmación visual antes de guardar
  • Ayuda contextual con ejemplos
Solución definitiva:
  • Solicitar autorización formal al Ingeniero Senior para conexión a base de datos institucional
  • Implementar lógica automática desde BD: si cantidad = 0 → No entregado
  • Si cantidad < prescrito → Parcial; Si cantidad = prescrito → Entregado
  • Validación automática de consistencia
R-06 CausaNoEntrega Inconsistente con EntTotal OPERATIVA Descripción: El campo EntTotal indica si la entrega fue completa (1) o parcial (0). Si no hay entrega o es parcial, debe especificarse CausaNoEntrega, pero puede haber inconsistencias al digitar ambos campos.

Consecuencias:
  • Rechazo por validación de MIPRES
  • Devoluciones de reportes
  • Retrasos en procesamiento
  • Confusión en trazabilidad
  • Reportes estadísticos incorrectos
 BAJA BAJO BAJO Mitigación inmediata:
  • Consultar catálogo de causas en el sistema SALUS
  • Verificar con el manual XLSX de Swagger de la clínica
  • Validación lógica manual antes de enviar
  • Si EntTotal = 1 → Verificar que CausaNoEntrega sea 0
  • Si EntTotal = 0 → Verificar que CausaNoEntrega esté seleccionada
  • Consultar al departamento de facturación en caso de duda
  • Lista desplegable con causas válidas del catálogo MIPRES
  • Mensaje de error visual si hay inconsistencia lógica
Solución definitiva:
  • Solicitar autorización formal al Ingeniero Senior para conexión a base de datos institucional
  • Implementar validación lógica automática desde BD
  • Campo CausaNoEntrega se habilita/deshabilita condicionalmente
  • Prevención automática de inconsistencias lógicas

Acciones Prioritarias

ACCIÓN CRÍTICA #1: Solicitar autorización inmediata al Ingeniero Senior para conexión a base de datos institucional y extracción automática de CUFE, códigos EPS, CUM y ConTec. Esto es la SOLUCIÓN DEFINITIVA que elimina los riesgos más críticos del proyecto.
ACCIÓN CRÍTICA #2 (Mientras tanto): Utilizar el sistema SALUS (sistema anterior de la clínica con acceso a BD) para consultar y verificar todos los datos necesarios. SALUS aún tiene conexión con la base de datos, aunque por actualización de BD y pérdida de código fuente no puede ser modificado.
Contexto del sistema SALUS: Es el sistema anterior de la clínica que se utilizaba para estas operaciones. Actualmente mantiene conexión con la base de datos institucional, pero debido a actualizaciones en la BD y pérdida del código fuente, no puede ser reparado ni modificado. Sin embargo, sigue siendo útil como herramienta de consulta para verificar datos.
Herramientas de soporte disponibles:
  • Sistema SALUS: Consulta de datos con acceso directo a BD
  • Manual XLSX de Swagger: Documento proporcionado por la clínica con instrucciones detalladas sobre cómo usar el Swagger y llenar cada campo correctamente
  • Cálculos manuales: Verificación matemática de valores y cantidades
  • Consulta a ingenieros: Verificación directa en base de datos para comparar datos impresos con registros actuales
  • Departamento de facturación: Canal de reporte para inconsistencias detectadas
Nota final: Esta matriz de riesgos será revisada y actualizada periódicamente durante el desarrollo e implementación del proyecto. Los planes de mitigación se ajustarán según las lecciones aprendidas y feedback del equipo de facturación.
