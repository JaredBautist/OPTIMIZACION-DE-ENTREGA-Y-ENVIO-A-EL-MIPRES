1. Metodología de Pruebas

Diseño del Experimento Comparativo

Se diseñó un experimento controlado para medir el impacto real de la aplicación desarrollada frente al método tradicional de uso directo del Swagger de MIPRES. El objetivo fue cuantificar las mejoras en tiempo, reducción de errores y experiencia del usuario.

Aspecto Detalle
Escenario de prueba Registro completo de 2 facturas, cada una con 2 prescripciones MIPRES
Total de operaciones 4 registros de prescripción por método (2 facturas × 2 prescripciones)
Métodos comparados Método A: Swagger UI de MIPRES (proceso tradicional)
Método B: Aplicación desarrollada (interfaz optimizada)
Usuario evaluador Personal del departamento de facturación de la Clínica San José
Métricas evaluadas • Tiempo promedio por factura
• Facilidad de uso percibida
• Cantidad de errores de digitación
• Disponibilidad de trazabilidad inmediata
⚠️ CONTEXTO IMPORTANTE - Limitaciones Actuales:

Durante las pruebas, aún NO se cuenta con autorización para conectar directamente a la base de datos institucional. Por lo tanto, la obtención de datos críticos se realizó mediante los siguientes métodos alternativos:

  • CUFE (Código Único de Facturación Electrónica): Consultado en la plataforma Facture (sistema de facturación electrónica de la clínica)
  • Código CUM (Código Único del Medicamento): Solicitado a ingeniero de soporte mediante consulta directa a la base de datos
  • Código EPS: Solicitado a ingeniero de soporte mediante consulta directa a la base de datos

Nota: Una vez obtenida la autorización del Ingeniero Senior para conexión a BD, estos datos se autocompletarán automáticamente, reduciendo aún más los tiempos de operación.

2. Resultados Comparativos

🔴 MÉTODO A: Swagger UI MIPRES

⏱️ 5 MINUTOS

por factura

Problemas identificados:
  • Recarga inesperada del formulario: El Swagger UI a veces se recarga automáticamente, haciendo que se pierdan los datos ingresados y obligando al usuario a comenzar de nuevo
  • Barrera técnica elevada: Requiere conocimientos sobre JSON, estructura de objetos y formato de datos
  • Interfaz no intuitiva: Campos técnicos sin explicaciones contextuales
  • Re-digitación constante: Cada prescripción requiere ingresar todos los datos desde cero, incluso si pertenecen a la misma factura
  • Sin validaciones previas: Los errores solo se detectan después del envío, cuando MIPRES responde con código 400
  • Trazabilidad manual: El usuario debe copiar/pegar las respuestas HTTP manualmente para llevar registro
  • Dependencia total de sistemas: Cada código (CUFE, CUM, EPS) requiere ticket o consulta presencial al área de sistemas

🟢 MÉTODO B: Aplicación Desarrollada

⏱️ 2 MINUTOS

por factura

Ventajas identificadas:
  • Persistencia de datos compartidos: Los campos comunes entre prescripciones de la misma factura se replican automáticamente, solo requiriendo cambiar ~7 campos específicos
  • Barrera técnica eliminada: Formularios con etiquetas claras en español, sin necesidad de entender JSON
  • Interfaz guiada paso a paso: Pestañas organizadas (EntregaAmbito, ReporteEntrega, Facturación)
  • Validaciones en tiempo real: Alertas inmediatas sobre campos obligatorios, formatos incorrectos o valores fuera de rango
  • Reporte automático generado: Archivo JSON descargable con todas las respuestas del día, listo para auditoría
  • Detección proactiva de errores: El usuario puede revisar el reporte diario ANTES de esperar glosas del Ministerio, permitiendo correcciones inmediatas
  • Reducción de dependencia: Aunque aún se requiere consultar códigos, la interfaz facilita su ingreso y reutilización
📊 MEJORA ALCANZADA: 60% DE REDUCCIÓN EN TIEMPO DE OPERACIÓN
(De 5 minutos a 2 minutos por factura)

6. Beneficio del Reporte Automático JSON

Comparación de Trazabilidad

Swagger UI - Trazabilidad Manual

Proceso:

  1. Enviar cada prescripción
  2. Copiar respuesta HTTP manualmente
  3. Pegar en Excel o Word
  4. Organizar manualmente por fecha
  5. Buscar errores revisando uno por uno

Tiempo adicional: ~5-10 minutos al final del día

Riesgo: Pérdida de información, errores al copiar IDs

Aplicación - Reporte Automático

Proceso:

  1. Realizar todos los envíos normalmente
  2. Clic en "Descargar reporte diario"
  3. Archivo JSON generado automáticamente con todos los registros
  4. Revisar éxitos/errores en formato estructurado
  5. Identificar problemas ANTES de esperar glosas del Ministerio

Tiempo adicional: ~30 segundos (solo descarga)

Ventaja: Detección proactiva de errores, evidencia inmutable para auditorías

💡 Beneficio Crítico: Detección Proactiva de Errores

El reporte JSON permite al personal de facturación identificar y corregir errores el MISMO DÍA del envío, sin necesidad de esperar semanas o meses a que el Ministerio de Salud emita una glosa (devolución de factura por inconsistencias).

Esto representa un ahorro significativo en tiempo administrativo, reduce el riesgo de pérdidas económicas por facturas rechazadas y mejora los indicadores de calidad del departamento de facturación.

10. Limitaciones Actuales y Mejoras Futuras

Limitaciones Identificadas durante las Pruebas

Limitaciones actuales:
  • Sin conexión a base de datos: Actualmente se requiere consultar manualmente CUFE (en Facture), códigos CUM y EPS (mediante ingenieros de soporte). Esto añade tiempo de espera y dependencia de terceros.
  • Persistencia limitada: Los datos compartidos se mantienen en la sesión actual pero no se guardan permanentemente. Al cerrar la aplicación, se pierden.
  • Sin histórico de facturas: No se mantiene un repositorio centralizado de todas las facturas enviadas a lo largo del tiempo.
  • Reportes diarios separados: Cada día genera un archivo JSON independiente, sin consolidación mensual/anual automática.

Mejoras Proyectadas con Autorización de BD

Mejoras esperadas al conectar la base de datos institucional:
  • Autocompletado total: CUFE, CodEPS, CUM y ConTec se cargarán automáticamente mediante búsqueda por número de factura o prescripción
  • Reducción adicional de tiempo: Se estima que el tiempo por factura podría reducirse de 2 minutos a 1-1.5 minutos (75% de mejora total vs. Swagger)
  • Eliminación de dependencia: El personal de facturación trabajará de forma completamente autónoma, sin necesidad de tickets a sistemas
  • Validaciones cruzadas: Verificar en tiempo real que el CUFE existe en el sistema de facturación electrónica
  • Histórico completo: Implementar base de datos local para almacenar todas las operaciones y generar reportes históricos
  • Dashboard analítico: Gráficos de tendencias, tasas de éxito/error, comparación mensual de productividad
🎯 META FUTURA: Reducir tiempo a 1 minuto por factura (80% de mejora vs. método original)

12. Conclusiones del Anexo

Hallazgos Principales

1. Reducción significativa de tiempo operativo:

La aplicación desarrollada demostró una reducción del 60% en el tiempo requerido para procesar facturas MIPRES, pasando de 5 minutos a 2 minutos por factura. Este ahorro se debe principalmente a la funcionalidad de datos compartidos y la eliminación de la barrera técnica.

2. Mejora en experiencia de usuario:

El personal de facturación expresó preferencia unánime por la aplicación desarrollada, destacando la interfaz intuitiva, las validaciones en tiempo real y la confianza que genera el sistema de trazabilidad automática.

3. Detección proactiva de errores:

El reporte JSON automático permite identificar y corregir problemas el mismo día del envío, sin necesidad de esperar glosas del Ministerio de Salud. Esto reduce riesgos económicos y mejora los indicadores de calidad del departamento.

4. Escalabilidad del impacto:

Proyectando el ahorro de 3 minutos por factura al volumen mensual/anual de la clínica, se estima un ahorro de 120 horas anuales (15 días laborales), que pueden ser redirigidas a tareas de mayor valor agregado.

5. Validación técnica exitosa:

El 100% de los envíos en ambos métodos fueron aceptados por MIPRES con código 200 OK, demostrando que la aplicación genera JSON válido y cumple con los estándares técnicos exigidos por el Ministerio de Salud.

6. Potencial de mejora adicional:

Una vez obtenida la autorización para conectar la base de datos institucional, se espera una reducción adicional del tiempo a 1-1.5 minutos por factura (75-80% de mejora total vs. método original), eliminando completamente la dependencia del área de sistemas.
